## 一、核心问题诊断

### 1.1 我们有什么

### 1.2 我们缺什么

**流量。**

当前核心矛盾：产品能力完备，但目标用户不知道我们的存在。

### 1.3 田野观察数据

我们做了一次 OpenClaw 养虾攻略实验：

```
100 人感兴趣
  → 30 人安装（30% 转化）
    → 10 人高强度使用（33% 留存）
      → 20 人中途放弃（67% 流失）
```

**关键发现：**
- ✅ 产品价值已验证（留存用户高强度使用）
- ❌ 瓶颈是门槛（70% 流失发生在安装 → 使用之间）
- 💡 B2D / B2C 边界模糊：AI Agent 让非开发者也具备了工具使用能力

**结论：** 不是产品不够好，是用户触达和使用门槛有问题。

## 二、GTM 核心策略

### 2.1 战略定位

```
传统 GTM：用户发现产品 → 阅读文档 → 安装配置 → 调试 → 使用 → 付费
我们的 GTM：用户打开网页 → 聊天体验 → 感知价值 → 两个选择：
  A. 继续用网页版（免费/基础）→ 付费升级
  B. 接入自己的 Agent（高级）→ 申请 API 计划
```

**核心转变：把"付费决策"从"安装之前"移到"体验之后"。**

### 2.2 与 ChatGPT / 通用 AI 的差异

| 通用 AI Chat | Antalpha Interactive Demo |
|-------------|-------------------------|
| "Aave USDC 收益大约 4.2%" | "Aave USDC 当前 APY **4.37%**，TVL **$12.3B**，DeFiLlama 实时数据，3 秒前更新" |
| "Merkl 是一个激励平台" | "Merkl 在 Base 链有 **23 个活跃激励池**，最高 APY 82.7%，[查看详情]" |
| 定性描述，无法验证 | **定量数据，链上可验证** |

**一句话差异：不是"聊天的 AI"，是"带真实链上工具的 AI"。**

## 三、Interactive Demo — 核心转化载体

### 3.1 为什么要做 Interactive Demo

传统获客路径：用户看到产品介绍 → 读文档 → 安装 → 配置 → 调试 → 70% 流失。

**我们的问题不是产品不好，是用户没机会感受产品有多好。**

Interactive Demo 解决的就是这个问题：
- 用户打开网页，说一句话，3 秒看到结果
- 不需要装任何东西，不需要理解任何技术
- 看到的不是 AI 的回答，而是**真实链上数据的实时结果**

**类比：** Vercel 的部署预览让你先看效果再决定部署。我们的 Demo 让用户先体验数据价值再决定接入。

### 3.2 用户体验核心理念

**一句话差异：ChatGPT 说"Aave 收益大约 4.2%"，Antalpha 显示"Aave USDC 当前 APY 4.37%，TVL $12.3B，DeFiLlama 实时数据，3 秒前更新"。**

用户 3 秒内就能感受到差异：这是真实数据，不是 AI 猜测。

### 3.3 Demo 体验设计

**用户进来看到什么：**
- 6 个预设按钮（"发现最佳收益"、"追踪聪明钱"、"模拟兑换"...）——零学习成本
- 输入框——用户可以用自然语言提问
- 每条回复附带数据来源标识——构建信任

**Demo 能做什么：**
- 📊 DeFi 收益发现——帮你找到 APY 最高的稳定币理财（数据来自 DeFiLlama）
- 🐋 聪明钱追踪——鲸鱼在买什么、卖什么（数据来自 Moralis 链上扫描）
- 🔄 DEX 兑换模拟——最优路由、滑点、Gas 全算好（数据来自 0x Protocol）
- 💰 多链钱包扫描——输入地址，12 条链余额一次看
- 📈 预测市场热度——当前最火的预测市场赔率（数据来自 Polymarket）
- 📊 收益对比——多个池子并排比，含风险调整评分

**交易怎么处理：** 模拟预览，不执行。用户看到完整的结果（路由、价格、滑点），但需要安装 MCP 才能真执行。这个设计自然地把 Demo 用户引导到下一阶段。

### 3.4 核心转化逻辑

```
访客进来 → 点一个按钮 → 3 秒看到真实数据 → "哇，这个跟 ChatGPT 不一样"
  → 试了第二个工具 → 又一个真实数据
    → "我想长期用" → 点击 "获取 API Key" → 注册
```

**关键：** 不是在说服用户，是在让用户自己说服自己。数据自己会说话。

### 3.5 增长飞轮

```
用户 A 用了 Demo → 分享分析结果（带链接）
  → 用户 B 看到链接 → 进入 Demo → 同样被数据打动 → 注册
    → 用户 B 也分享 → 用户 C, D, E...
```

每条分析结果都是一个可传播的触点。这个飞轮在产品功能的支持下自动转。

#### Agent Referral（智能体推销员）

**核心思路：让其他 OpenClaw Agent 帮我们推广。**

这是增长黑客最经典的 Referral 渠道，但适配到了 AI Agent 场景：

```
传统 Referral：用户 A 推荐用户 B → 奖励 A
Agent Referral：Agent A 使用 Antalpha MCP → Agent A 的主人看到效果 → 主人推荐给 Agent B 的主人
```

**为什么这个策略独特且不可复制：**
- OpenClaw 是我们的底层框架，装了 MCP 的 Agent 自然会展示数据来源
- 每次 Agent 输出结果都会显示 "Powered by Antalpha MCP" → 其他的 Agent 主人看到
- 这不是我们在推产品，是用户的真实 Agent 在帮我们推

**具体实现：**

| 方案 | 说明 |
|------|------|
| **水印式 Referral** | 所有工具返回的 JSON 中嵌入 `source: "Antalpha MCP"` + `ref_link` |
| **Agent 推荐码** | 注册时输入 referrer 的 agent_id，双方各获 bonus 额度 |
| **社交分享模板** | 生成的结果附带可分享链接，含来源追踪 |
| **Referral 仪表盘** | 追踪哪些 Agent 带来了注册和调用 |

**⚠️ 实现复杂度：** Agent Referral 不是几个小时能搞定的。需要工程投入：水印嵌入涉及所有工具返回结构改造，推荐码需要注册流程变更，仪表盘需要数据追踪体系。建议作为 Phase 1 重点工程任务，由专人负责。当前阶段先做最小可行版本（仅水印嵌入），后续迭代其他方案。

**转化路径：**
```
Agent A 装了 Antalpha MCP
  ↓ 查询 DeFi 收益
  ↓ 输出结果中含 "Powered by Antalpha MCP" + ref 链接
  ↓ Agent B 的主人看到
  ↓ 点击链接 → 注册 API Key → Agent B 也装了 Antalpha MCP
  ↓ Agent A 的主人获得 bonus 额度
```

**关键数据点：**
- OpenClaw 养虾攻略实验中，100 人试用 → 30% 安装 → 10% 高频使用
- 如果这 30 人每人影响 2-3 个朋友 → 60-90 个新用户，成本为零
- **这是 0 预算、产品自驱动的增长飞轮**

## 七、风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| Demo 上线后无人使用 | 流量获取失败 | 加强第二波内容种草 + 第三波社群渗透 |
| 内容暴露技术细节 | 竞争对手抄袭 | 严格执行"只展示结果"原则 |
| 用户体验后不转化 | 转化率低于预期 | 分析工具使用数据，优化 CTA 和 Demo 体验 |
| 线下展会 ROI 低 | 参展后无转化 | 只做 Lightning Demo（低成本高密度接触），不做大展位 |
